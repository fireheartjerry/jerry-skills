# Evals for competitive-systems

These files let anyone check the claim that the skill changes an agent's behaviour, using the
same scenarios, fixtures and grading rules as the published results (`results.md`).

## Files

| File | What it is |
|---|---|
| `scenarios.json` | 14 scenarios (S-A to S-N; S-M and S-N were added after the published run and have no results yet): situation, user message, fixture, musts, failure modes, mechanical probes, and whether the scenario guards a strength of the previous version |
| `rubric.md` | The rubric in readable form, generated by `grade.py --rubric`; lint fails if it drifts from scenarios.json |
| `trigger.json` | Prompts that should and should not route to this skill (near misses included), plus decoy skills: fixed descriptions, and this repository's sibling skills read live (`from_skill`) |
| `fixtures/make_fixtures.py` | Writes every fixture deterministically (seeded, offline); also the fixtures behind worked examples A and B |
| `run_eval.py` | Runs the scenarios with and without the skill through `claude` or `codex`; `--trigger` runs the routing check |
| `grade.py` | Mechanical grading, independent-grader prompts, merging, rubric generation |
| `results.md` | The published run: method, n, scores, cost and limits |

## Arms and runners

- `none`: the agent gets the user message and the fixture, nothing else. Skills and slash
  commands are disabled (`--disable-slash-commands`) so an installed copy of this skill
  cannot load.
- `skill`: as `none`, plus SKILL.md appended to the system prompt and a snapshot of the skill
  directory (without `evals/` and `tests/`) added with `--add-dir`.
- Runners: `claude -p ... --output-format stream-json` (tools Read, Glob, Grep, Write, Edit,
  Bash; a per-run cap `--max-budget-usd`, default 3) and `codex exec --json` (the skill text
  is prepended to the prompt, since `codex exec` has no system-prompt flag). Each run works
  in a fresh copy of its fixture under the system temp directory, outside any repository.
- The model's sampling cannot be seeded: `--seeds N` labels N repeats.
- The prompt is the scenario's user message, closed with a full stop when it has no final
  punctuation, then `The relevant files are in the current directory.` as its own paragraph.

## Permissions and isolation

Read this before a live run. The claude runner uses `--permission-mode dontAsk` with Bash
allowed: the agent runs shell commands as you, unsandboxed, with your files and network in
reach. `--setting-sources project`, `--strict-mcp-config` and `--disable-slash-commands`
keep your user settings, MCP servers and skills out of both arms, but nothing stops Bash from
reading an installed copy of this skill. Run live evals in a container or a disposable user
account that has no copy of the skill and nothing you would mind an agent touching.

The codex runner uses `--sandbox workspace-write` and an isolated `CODEX_HOME`
(`OUT/codex-home`, holding only a copy of `auth.json`), so `~/.codex` skills, `AGENTS.md`
and config reach neither arm.

`grade.py --transcripts` lists every no-skill transcript whose tool calls mention `SKILL.md`
or `competitive-systems`; a non-zero count means the baseline was contaminated.

## Reproduce (from the skill directory)

```
python3 evals/fixtures/make_fixtures.py --list
python3 evals/run_eval.py --dry-run                     # prints 4 commands per scenario (56), spends nothing
python3 evals/run_eval.py --runner claude --arms none,skill --seeds 2 --jobs 4 --max-total-usd 10 --yes
python3 evals/run_eval.py --runner claude --trigger --yes
python3 evals/grade.py --transcripts OUT --out OUT/grades.md     # also writes OUT/grades.json
```

Spend guards: a live run prints the worst case (runs x the per-run cap, `--max-budget-usd`,
default 0.75) and needs `--yes`; it stops submitting runs once the reported cost reaches
`--max-total-usd` (default 1.00, so a full run needs it raised on purpose). Codex reports no
cost, so a live codex run needs `--max-runs`. A timed-out run's whole process group is killed.

`OUT` defaults to `eval-runs/competitive-systems/runs` inside the skills repository and
`./eval-runs` elsewhere. Reruns skip finished runs; `--force` repeats them. Cost: the
published run measured 0.05 to 0.53 USD per scenario run with the default Claude model,
about 0.04 USD per trigger prompt and 0.01 to 0.05 USD per independent grade; see
`results.md` for the totals.

## Grading

1. Mechanical: `grade.py --transcripts` applies each scenario's probes (case-insensitive
   regexes over the agent's own messages, tool calls or file edits, and shell commands run
   in the kept work directory). Score = must probes matched minus failure probes matched;
   every hit is listed with the line that matched, so a reader can audit it. Probes tagged
   `requires_skill_tool` (and, for the grader, the musts listed in `skill_tool_musts`) check
   that the agent ran one of the skill's own commands, which the `none` arm cannot do; the
   outcome score leaves them out, and both scores are reported.
2. Independent: for each transcript, `grade.py --prompt SID TRANSCRIPT` prints a prompt with
   the musts, failure modes and transcript (no regexes). Give it to a different model or a
   fresh session that has seen nothing else, and save the reply as
   `<transcript>.grade.txt`. The implementer of the skill never grades. For example:

   ```
   for t in OUT/*/S-*.md; do
     sid=$(basename "$t" | cut -d. -f1)
     python3 evals/grade.py --prompt "$sid" "$t" | claude -p --model sonnet --tools "" \
       --system-prompt "You grade transcripts strictly against the rubric given." > "$t.grade.txt"
   done
   python3 evals/grade.py --merge OUT/grades.json --out OUT/grades-merged.md
   ```
