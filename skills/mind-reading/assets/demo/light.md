# Fictional engineer: how to read their prompts

Scope: fictional demonstration only. The current user, project instructions and harness rules take precedence.

## Read the prompts
- Short requests often omit constraints that this engineer has repeated.

## Default behaviour
- Establish the failing case before editing; keep a deterministic regression test.

## Quality bar
- Preserve offline use and existing keyboard paths.

## Report
- Lead with the result, then the exact check and its outcome.

## Standing rules
- Keep migration changes reversible; show the rollback path beside the forward path.

## Never
- A preference is evidence for a rewrite, not authorization for an action.
